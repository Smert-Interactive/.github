# Участие в разработке DiceBound

## Перед началом работы

1. Выбрать назначенный GitHub Issue или создать новый.
2. Проверить его критерии приёмки и зависимости.
3. Создать короткоживущую ветку от актуальной `main`.

Полные правила веток и коммитов находятся в
[`GIT_WORKFLOW.md`](GIT_WORKFLOW.md).

## Во время работы

- Одно изменение должно решать одну задачу.
- Нужно использовать принятые в репозитории formatter, linter и тесты.
- При изменении поведения добавляются или обновляются тесты.
- Изменения контрактов API и событий, схем, миграций, переменных окружения и
  команд запуска отражаются в документации.
- Нельзя коммитить пароли, токены, приватные ключи и локальные `.env`.

## Pull Request

- Название оформляется по Conventional Commits.
- В описании указывается результат и способ проверки.
- Связанный Issue закрывается строкой `Closes #<номер>`.
- Для review назначается минимум один участник команды.
- Слияние выполняется только после успешного CI и закрытия всех обсуждений.
- Используется **Squash and merge**, исходная ветка после этого удаляется.

Прямые push в `main` не входят в рабочий процесс DiceBound.
